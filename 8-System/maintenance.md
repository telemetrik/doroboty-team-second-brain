# Utrzymanie wiedzy

| Moment | Działanie |
| --- | --- |
| Przed pracą | Sprawdź istniejące ustalenia, dowody i luki. |
| Po badaniu, eksperymencie lub decyzji | Zaktualizuj istniejące strony przez PR. |
| Po zauważeniu błędu | Przygotuj poprawkę lub Issue z dowodem i pytaniem do rozstrzygnięcia. |
| Co tydzień | Opiekun przeznacza początkowo 20-30 minut na kolejkę Issues, PR-y i ustalenie napraw. |
| Przy zamknięciu projektu | Dopisz syntezę i przenieś trwałe wnioski do ich właściwego miejsca. |
| Przy zmianie zespołu | Przekaż obszar, aktywne przeglądy i odpowiedzialność za review. |

Uruchom [team-garden](../.agents/skills/team-garden/SKILL.md), aby zebrać problemy i propozycje. GitHub Issues to kolejka utrzymania. Przy rozstrzygnięciu odsyłaj z PR-a do Issue, a w dokumencie zastąpionym zachowaj odnośnik do następcy. `reviewed_at` zmienia się po rzeczywistym przeglądzie merytorycznym.
